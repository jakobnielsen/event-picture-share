# Event Photo Share — Project Plan

A free-to-host PWA that lets event attendees upload photos to the organizer's Google Drive by scanning a QR code. No subscriptions, no third-party storage.

---

## Architecture

| Layer | Technology | Reason |
|---|---|---|
| Frontend | React + Vite → GitHub Pages | Free static hosting, PWA-installable |
| Backend | Google Apps Script Web App | Free, serverless, reads/writes Google Drive |
| Storage | Google Drive (one subfolder per event) | Organizer's own Drive, no extra cost |
| QR Code | Client-side (`qrcode` npm library) | No external service, works offline |
| CI/CD | GitHub Actions (two parallel jobs) | Fully automated — push to `main` deploys everything |

### URL scheme

| Page | URL |
|---|---|
| Attendee upload | `https://<user>.github.io/event-picture-share/?token=EVENT_TOKEN` |
| Organizer admin | `https://<user>.github.io/event-picture-share/#admin` |
| Landing (no token) | `https://<user>.github.io/event-picture-share/` |

The token is a 32-character random string generated per event. Apps Script validates it before accepting any upload. The admin key is a separate secret — never committed to the repo.

## Apps Script API (`apps-script/Code.gs`)

A single `doGet` + `doPost` dispatcher. All POST bodies are JSON.

| Method | Action | Auth | Description |
|---|---|---|---|
| GET | `getEvent` | token | Returns event name for the upload page header |
| POST | `upload` | token | Decodes base64 file and saves to event Drive folder |
| POST | `createEvent` | adminKey | Creates Drive subfolder, generates token, persists event |
| POST | `listEvents` | adminKey | Returns all events with folder URLs |

**Script Properties** (set once in the Apps Script editor — never in source):

| Property | Value |
|---|---|
| `ADMIN_KEY` | Long random string. Guards `createEvent` and `listEvents`. |
| `PARENT_FOLDER_ID` | Google Drive folder ID that will contain all event subfolders. |
| `EVENTS` | JSON array auto-managed by the script. Starts as `[]`. |

## Image compression strategy (quality-first)

| File size | Action |
|---|---|
| < 5 MB | Upload original — no compression at all |
| 5 – 15 MB | Compress: quality-reduction only (`alwaysKeepResolution: true`), target 5 MB |
| > 15 MB | Compress: quality-reduction only, target 8 MB; show warning badge |

Settings for all compression: `initialQuality: 1`, `preserveExif: true`, `useWebWorker: true`.  
HEIC (iPhone default) is automatically converted to JPEG by `browser-image-compression`.

## Deployment — fully automated via GitHub Actions

Every push to `main` triggers two parallel jobs:

### Job 1 — `deploy-frontend`
1. `npm ci`
2. `npm run build` (with `VITE_APPS_SCRIPT_URL` injected from secrets)
3. Deploy `dist/` to `gh-pages` branch via `peaceiris/actions-gh-pages`

### Job 2 — `deploy-apps-script`
1. Write `CLASPRC_JSON` secret to `~/.clasprc.json`
2. `clasp push --force` (uploads `Code.gs` and `appsscript.json`)
3. `clasp deploy --deploymentId $CLASP_DEPLOYMENT_ID` (creates new version + updates the live web app)

### Required GitHub Secrets

| Secret | How to get it |
|---|---|
| `VITE_APPS_SCRIPT_URL` | The `https://script.google.com/macros/s/.../exec` URL from the Apps Script deployment |
| `CLASPRC_JSON` | Contents of `~/.clasprc.json` after running `clasp login` locally |
| `CLASP_DEPLOYMENT_ID` | Deployment ID from the first manual deploy (shown in Apps Script editor → Deploy → Manage deployments) |

## One-time manual bootstrap (before CI takes over)

These steps are done once by the organizer on their local machine:

1. **Install clasp** globally: `npm install -g @google/clasp`
2. **Authenticate**: `clasp login` (opens browser OAuth flow) → creates `~/.clasprc.json`
3. **Create the Apps Script project**:
   ```sh
   cd apps-script
   clasp create --type webapp --title "event-picture-share"
   ```
   This writes `.clasp.json` with the script ID. **Commit this file.**
4. **Initial push**: `clasp push`
5. **Deploy as web app** in the Apps Script editor:
   - Click **Deploy → New deployment**
   - Type: **Web app**
   - Execute as: **Me**
   - Who has access: **Anyone** (anonymous)
   - Click **Deploy** → copy the deployment URL and deployment ID
6. **Set Script Properties** (Apps Script editor → Project Settings → Script Properties):
   - `ADMIN_KEY` — generate a long random string (e.g. `openssl rand -hex 32`)
   - `PARENT_FOLDER_ID` — the Drive folder ID from your Google Drive URL
   - `EVENTS` — set to `[]`
7. **Store GitHub Secrets** (repo Settings → Secrets and variables → Actions):
   - `VITE_APPS_SCRIPT_URL` — the deployment URL from step 5
   - `CLASPRC_JSON` — `cat ~/.clasprc.json`
   - `CLASP_DEPLOYMENT_ID` — the deployment ID from step 5
8. **Enable GitHub Pages** (repo Settings → Pages):
   - Source: **Deploy from a branch**
   - Branch: `gh-pages` / `/ (root)`
9. **Generate PWA icons** (run once after cloning):
   ```sh
   node scripts/generate-icons.js
   ```
   Replace `public/icons/icon-192.png` and `public/icons/icon-512.png` with your own artwork if desired.

After this, every `git push origin main` deploys everything automatically.

## Security model

- **Upload tokens** — random 32-char string per event, embedded in the QR code URL. No token → no upload accepted.
- **Admin key** — stored only in Apps Script Script Properties and in the organizer's browser `localStorage`. Never in source code or build output.
- **Apps Script URL** — treated as a build-time env var via `VITE_APPS_SCRIPT_URL`. Baked into the static bundle at deploy time; not sensitive on its own (the token/adminKey gate the actual operations).
- **CORS** — POST requests use `Content-Type: text/plain` to avoid CORS preflight (Apps Script does not handle OPTIONS). The JSON body is parsed server-side regardless.
