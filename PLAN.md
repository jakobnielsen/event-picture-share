# Event Photo Share — Project Plan

A free-to-host PWA that lets event attendees upload photos and videos to the organizer's Google Drive by scanning a QR code. No subscriptions, no third-party storage.

---

## Architecture

| Layer | Technology | Reason |
|---|---|---|
| Frontend | React 19 + Vite + TypeScript → GitHub Pages | Free static hosting, PWA-installable |
| Backend | Google Apps Script Web App | Free, serverless, issues Drive OAuth tokens |
| Storage | Google Drive (one subfolder per event) | Organizer's own Drive, no extra cost |
| Upload | Browser-initiated Drive resumable uploads | No size limit, real XHR progress, CORS-safe |
| QR Generation | Client-side (`qrcode` npm library) | No external service, works offline |
| QR Scanning | Camera + `jsQR` in-browser | Scan QR directly from the landing page |
| i18n | Custom React context | English and Danish, auto-detected from browser |
| CI/CD | GitHub Actions (two parallel jobs) | Fully automated — push to `main` deploys everything |

### URL scheme

| Page | URL |
|---|---|
| Attendee upload | `https://<user>.github.io/event-picture-share/?token=EVENT_TOKEN` |
| Organizer admin | `https://<user>.github.io/event-picture-share/#admin` |
| Landing (no token) | `https://<user>.github.io/event-picture-share/` |

The token is a 32-character random string generated per event. Apps Script validates it before accepting any upload. The admin key is a separate secret — never committed to the repo.

## Apps Script API (`apps-script/Code.gs`)

A single `doGet` + `doPost` dispatcher. All POST bodies are sent as `Content-Type: text/plain` (JSON parsed server-side) to avoid CORS preflight.

| Method | Action | Auth | Description |
|---|---|---|---|
| GET | `getEvent` | token | Returns event name for the upload page header |
| POST | `createUploadSession` | token | Validates token (checks expiry + revoked), returns Drive OAuth token + folder ID + safe filename for browser to initiate a Drive resumable upload session directly |
| POST | `createEvent` | adminKey | Creates Drive subfolder, generates token, persists event with expiry date |
| POST | `listEvents` | adminKey | Returns all events with status fields |
| POST | `revokeEvent` | adminKey | Marks an event as closed — uploads immediately rejected |
| POST | `reopenEvent` | adminKey | Clears revoked flag; extends `expiresAt` if expired |
| POST | `deleteEvent` | adminKey | Removes event record; optionally moves Drive folder to trash |

### Upload flow

1. Browser calls `createUploadSession` → receives `{ uploadToken, folderId, safeName }`
2. Browser POSTs to `https://www.googleapis.com/upload/drive/v3/files?uploadType=resumable` with the OAuth token — gets back a `Location` header (session URL)
3. Browser PUTs raw file bytes to the session URL via XHR for real progress reporting
4. On failure, browser queries Drive with `Content-Range: */<size>` to get resume offset (HTTP 308), then re-sends remaining bytes
5. Auto-retry up to 3 times with exponential backoff; manual retry button per file

This approach is CORS-safe because the browser itself initiates the Drive session (Origin header present → Drive sets CORS headers).

**Script Properties** (set once in the Apps Script editor — never in source):

| Property | Value |
|---|---|
| `ADMIN_KEY` | Long random string. Guards `createEvent`, `listEvents`, `revokeEvent`, `reopenEvent`, `deleteEvent`. |
| `PARENT_FOLDER_ID` | Google Drive folder ID that will contain all event subfolders. |
| `EVENTS` | JSON array auto-managed by the script. Starts as `[]`. Each entry: `{ token, name, folderId, folderUrl, createdAt, expiresAt, revoked }`. |

**Storage limits**: Script Properties support ~9 KB per value. Each event is ~250 bytes, giving a practical ceiling of ~35 events. If you expect more, migrate `EVENTS` to a Google Sheet.

## Upload behaviour

- **No compression** — files are uploaded as-is to preserve quality. Google Drive accepts original photos and videos.
- **Duplicate prevention** — before initiating a session, Apps Script checks if a file with the same name already exists in the folder. Duplicates are skipped and marked as already uploaded.
- **Concurrency** — 3 parallel uploads (conservative for 4G mobile connections; safe on both iOS and Android).
- **Resumable uploads** — each upload uses Drive's resumable upload protocol, so interrupted uploads can be resumed mid-file.
- **Wake Lock** — the Screen Wake Lock API keeps the screen on during uploads so the browser stays active.
- **File types** — `image/*` and `video/*` accepted.

## Deployment — fully automated via GitHub Actions

Every push to `main` triggers two parallel jobs:

### Job 1 — `deploy-frontend`
1. `npm ci`
2. `npm run build` (with `VITE_APPS_SCRIPT_URL` injected from secrets)
3. Deploy `dist/` to `gh-pages` branch via `peaceiris/actions-gh-pages`

### Job 2 — `deploy-apps-script`
1. Write `CLASPRC_JSON` secret to `~/.clasprc.json`
2. `clasp push --force` (uploads `Code.gs` and `appsscript.json`)
3. `clasp deploy --deploymentId $CLASP_DEPLOYMENT_ID` (creates new version + updates the live web app)

### Required GitHub Secrets

| Secret | How to get it |
|---|---|
| `VITE_APPS_SCRIPT_URL` | The `https://script.google.com/macros/s/.../exec` URL from the Apps Script deployment |
| `CLASPRC_JSON` | Contents of `~/.clasprc.json` after running `clasp login` locally |
| `CLASP_DEPLOYMENT_ID` | Deployment ID from the first manual deploy (shown in Apps Script editor → Deploy → Manage deployments) |

## One-time manual bootstrap (before CI takes over)

These steps are done once by the organizer on their local machine:

1. **Install clasp** globally: `npm install -g @google/clasp`
2. **Authenticate**: `clasp login` (opens browser OAuth flow) → creates `~/.clasprc.json`
3. **Create the Apps Script project**:
   ```sh
   cd apps-script
   clasp create --type webapp --title "event-picture-share"
   ```
   This writes `.clasp.json` with the script ID. **Commit this file.**
4. **Initial push**: `clasp push`
5. **Deploy as web app** in the Apps Script editor:
   - Click **Deploy → New deployment**
   - Type: **Web app**
   - Execute as: **Me**
   - Who has access: **Anyone** (anonymous)
   - Click **Deploy** → copy the deployment URL and deployment ID
6. **Set Script Properties** (Apps Script editor → Project Settings → Script Properties):
   - `ADMIN_KEY` — generate a long random string (e.g. `openssl rand -hex 32`)
   - `PARENT_FOLDER_ID` — the Drive folder ID from your Google Drive URL
   - `EVENTS` — set to `[]`
7. **Store GitHub Secrets** (repo Settings → Secrets and variables → Actions):
   - `VITE_APPS_SCRIPT_URL` — the deployment URL from step 5
   - `CLASPRC_JSON` — `cat ~/.clasprc.json`
   - `CLASP_DEPLOYMENT_ID` — the deployment ID from step 5
8. **Enable GitHub Pages** (repo Settings → Pages):
   - Source: **Deploy from a branch**
   - Branch: `gh-pages` / `/ (root)`
9. **Generate PWA icons** (run once after cloning):
   ```sh
   node scripts/generate-icons.js
   ```
   Replace `public/icons/icon-192.png` and `public/icons/icon-512.png` with your own artwork if desired.

After this, every `git push origin main` deploys everything automatically.

## Security model

- **Upload tokens** — random 32-char string per event, embedded in the QR code URL. No token → no upload accepted.
- **Admin key** — stored only in Apps Script Script Properties and in the organizer's browser `localStorage`. Never in source code or build output.
- **Apps Script URL** — treated as a build-time env var via `VITE_APPS_SCRIPT_URL`. Baked into the static bundle at deploy time; not sensitive on its own (the token/adminKey gate the actual operations).
- **CORS** — POST requests use `Content-Type: text/plain` to avoid CORS preflight (Apps Script does not handle OPTIONS). The JSON body is parsed server-side regardless.

## Features

- ✅ PWA — installable, offline-capable via Workbox precaching
- ✅ QR code scanning directly from the landing page (jsQR + camera)
- ✅ Photo and video upload (any `image/*` or `video/*`)
- ✅ Browser-initiated Drive resumable uploads (no size limit, real progress)
- ✅ Auto-retry with exponential backoff + manual retry per file
- ✅ Wake Lock keeps screen on during uploads
- ✅ Token expiry — configurable per event (default 14 days, max 365)
- ✅ Event revocation — organizer can close an event at any time
- ✅ Event reopening — closed/expired events can be reopened with extended expiry
- ✅ Event deletion — removes event record with optional Drive folder trash
- ✅ Duplicate upload prevention — same filename skipped if already in Drive folder
- ✅ Dark mode (CSS custom properties, persisted to localStorage)
- ✅ English + Danish i18n (auto-detected, persisted to localStorage)
- ✅ Admin dashboard — create events, show/download QR codes, link to Drive folders
- ✅ Multiple concurrent events with unique tokens

## Out of scope (current version)

- Gallery / viewing uploaded photos
- User accounts beyond the admin key
- Server-side rate limiting
